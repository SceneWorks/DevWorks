# Project overview and activity

Overview summarizes the selected project. Its summary strip separates Features, Issues, Working, and Needs you. Activity is inside Overview, not a separate global navigation destination. Follow a work or activity link to inspect the authoritative record and its revision.

## Read status carefully

A planned action, an accepted command, a tool attempt, an observed external effect, and a verified outcome are different facts. An agent saying it finished or a process returning zero does not establish that delivery criteria passed. Use the linked evidence, review, Git, and operation records. A pending operation can need reconciliation even when its originating conversation is closed.

Use filters to focus activity without changing the work itself. Pages are bounded. Continue with the returned cursor; if the cursor expires, refresh the filtered view rather than combining pages from different snapshots. Current permissions and project visibility still apply to history and artifacts.

## Continue existing work

Open the affected feature or issue before starting another execution owner. A paused root retains its history and independent blockers. Continue should reconcile the prior owner and current state, not duplicate it. Completion, dependency changes, and approvals can make some work eligible while other holds remain. See [Work controls](help:work-controls), [Features](help:features), and [Issues](help:issues).

When the view cannot obtain a current source, treat its last data as stale. The diagnostics or operation link is more useful than repeatedly clicking Start. Work outside this project remains independent unless a real shared dependency or resource reservation applies.
