# Container runtime preferences

The preferred runtime setting can name Docker, Podman or Apple. The app must detect and qualify the selected runtime rather than silently substituting another backend. A stored choice is not a claim that container execution exists in this build. If unavailable, use the reported capability status; native executable packages still run under their documented user-rights guarantee and must not be described as container-sandboxed.

## Apply a change

Choose the intended scope, read the effective value/source, edit, validate, and save or propose through the app. Keep the original draft and operation identity if the result is uncertain. For a revision conflict, refresh and explicitly review/rebase before retrying. Adoption timing and harness-enforced restrictions are listed in the [Complete settings reference](help:settings-reference).
