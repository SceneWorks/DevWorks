# Explore repository code

Open **Repositories**, choose a registered repository, then open its code view. **Overview** shows the repository facts and any captured README. **Captured scope overview** shows the repositories covered by the selected scope and capture. **Browse nodes** groups indexed entries by kind and container; expand containers, filter by node kind or internal module, and use the page controls to continue. **Search graph** offers ranked nodes, a node list, or repositories and nodes. Search the selected repository or the captured scope.

Choose a node to inspect its description, confidence, properties, incoming and outgoing relationships, and retained source location. Read its source window, code snippet, or whole file. **Explore a source file** reads an explicit repository-relative file or line window, finds its indexed nodes, and shows file impact. Source pages preserve Unicode and can continue partway through a long line. A directory or source-less node does not supply a source citation.

**Explore calls, impact and data flow** follows callers, callees, dependencies, impact, consumers and publishers from a selected node or an entered name. Depth and relationship filters apply to the shared reader. Repository links let you inspect either end; unavailable targets remain unavailable. **Graph schema** describes indexed kinds and relationships, or the declared schema when no index exists. This is separate from [database schema exploration](help:databases).

Every drill-down stays on one captured repository view until you choose **Refresh selected graph view**. The captured README and source come from that view, even if the checkout changes. **Current scope** uses the application's authorized current selection. **Published repository** and **Exact indexed view** are explicit choices; a missing requested view produces an error rather than silently choosing another one. Worktree-bound reads never fall back to another branch. Back navigation preserves the captured view; leaving code exploration keeps your chat draft.

Partial coverage, missing indexes, unavailable source and absent analysis are shown explicitly. Internal module summaries, provenance and program totals appear only when analysis has actually been recorded. Indexed node counts remain separate observations. **Mark untrusted** lowers ranking; it does not grant permissions or erase the entry. If a trust change cannot be confirmed, use **Confirm outcomes** to check the same request before making another change.

For missing or stale data, inspect [Indexing](help:indexing) runs and the [repository registration](help:repositories). Re-observe repository discovery after a branch or head change, then request indexing through its own controls. Health measurements and review history are unavailable where their producers have not supplied them.
