# GitHub account and synchronization settings

Keep account credentials in the native secret facility. Settings describe synchronization/review behavior; current GitHub adapter availability, remote identity and permissions still apply. Distinguish an observed remote review or merge from a locally planned action. Refresh authoritative PR state before consequential delivery decisions, and reconcile a timed-out mutation before retrying. A stored preference is not a promise that every GitHub synchronization service is installed. GitHub polling, issue import, linked issue updates and issue triage are not yet active: Settings marks those rows "Not yet active" and saving them changes nothing.

## Apply a change

Choose the intended scope, read the effective value/source, edit, validate, and save or propose through the app. Keep the original draft and operation identity if the result is uncertain. For a revision conflict, refresh and explicitly review/rebase before retrying. Adoption timing and harness-enforced restrictions are listed in the [Complete settings reference](help:settings-reference).

See [Settings overview](help:settings), [Permissions](help:permissions), and [Recovery](help:recovery).
