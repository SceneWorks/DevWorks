# Git, reviews, and delivery evidence

Git operations act on registered repositories and owned task worktrees. Inspect the actual branch, HEAD, worktree identity, remote, and relevant artifact before committing, pushing, or opening/updating a pull request. A display label or old screenshot does not identify current source.

Owned commit review binds the actual changed content and message. Changed files after review can make the proposed commit stale. A force push needs the required exact authority and ownership and must retain protected/default-branch safeguards. Human approval does not become broad Git permission.

## Verification and review

Keep the tested source identity with verification evidence. Arrange review for the actual candidate head and resolve material findings before claiming delivery. A successful local command, opened PR, or reported child success is not verified completion. Branch changes can invalidate prior browser or test evidence; retain useful history without presenting stale evidence as current.

Review and delivery Settings record policy. The action still needs its qualified Git/GitHub runtime and current permissions. If sync or a remote request is unavailable, distinguish known local state from an unobserved remote outcome. Avoid repeating a push or PR mutation with a fresh identity after a timeout; reconcile the original operation first.

Project deletion never cleans up local repositories or GitHub resources. Worktree cleanup is separate from artifact retention. See [Repositories](help:repositories), [Browser evidence](help:browser), [Approvals](help:approvals), and [Recovery](help:recovery).
