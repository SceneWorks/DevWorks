# Databases and schema capabilities

The Databases destination groups database connections and schema exploration. A designed tab is not a claim that every database driver or browser is available. Use the current capability status and diagnostics to distinguish a configured record from a successful connection or a published schema index.

Registered schema-indexing and retrieval actions, where available, read a particular source revision and publish managed evidence. A failed refresh must not masquerade as an empty successful schema. Rows and credentials can be sensitive; current project/tool permissions and redaction policy still apply. Do not paste connection passwords into messages or diagnostics.

Use a schema snapshot's source identity and revision when reporting relationships. A query against one coherent published view is different from a live database mutation. The app must not infer authority to execute SQL simply because it can inspect metadata. Database data tools are not yet active: data read access, data write access, separately authorized writes and the ReadOnly and ReadWrite tool exposures are saved with a source but change nothing, and the form says so beside them.

If this build exposes no qualified database operation, this page remains an honest unavailable entry rather than a substitute browser. Existing repository indexing, local Knowledge, and Help remain usable independently. See [Indexing](help:indexing), [Diagnostics](help:diagnostics), [Permissions](help:permissions), and [Capability reference](help:capability-reference).
