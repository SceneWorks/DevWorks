# Embedding-space persistence qualification

DW-119 retains immutable candidate configuration and canonical space identity separately from append-only qualification revisions and an append-only explicit-selection singleton. Selection starts at revision 1 with no selected candidate or space. Nothing derives an embedding route from a conversation, discovery ordering, pricing, or an initial model.

The semantic identity includes the exact connection/account generation, endpoint, literal upstream model, encoder configuration, dimension mode/count, metric and Float32 encoding. Display names and billing metadata do not change it. Changed semantic configuration creates a different canonical space; an existing vector-space row is never relabelled.

Qualification retains two distinct real operations: the outer durable qualification intent and the native router request operation. A host-verified proof can be staged while the exact outer attempt is Dispatching, or during same-attempt Unknown/NeedsInput recovery. Staging checks original store/restore/authority fences, native request/admission/actor/scope identity, exact completed native attempt, quiescent Completed accounting, current admitted connection revision, and exact live manifest/vector artifact metadata. It does not read files or run inference inside the writer. A native result that completed before a crash can be recovered with the same request/admission identity and latest outer fence; another boot is not permission to issue a new probe.

Only the exact outer ObservedComplete attempt can publish Qualified from already staged proof. Durable cancellation before publication blocks qualification and vector-space registration while preserving the completed/accounted native result. An explicit selected space additionally requires a separate selection CAS and candidate qualification revision. Current semantic identity and retained evidence are rechecked; a later cosmetic connection revision does not invalidate the original admitted identity.

The focused real SQLite cases cover page boundaries, the full declared name bound, immutable identities, both CAS levels, stage/complete ordering, cross-intent identity reuse, stale fences, restart recovery, restore fencing, account changes, cosmetic edits, cancellation, and collision rollback. All native cases and affected strict lint pass; exact commands, source hashes and migration checks are recorded in `results.json`.

This is persistence evidence on Darwin, not provider execution or whole-item acceptance. The native executor separately verifies the complete result manifest, raw vector bytes, dimensions, finiteness, Cosine norm, fixed probe input and host provenance. Artifact retention uses its owning service rather than hidden writes from this adapter.
